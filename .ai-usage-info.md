# MICX Sec VCS SDK — purpose and use

PHP 8.3+, namespace `Micx\Vcs`, entry point `MixVcsManager`.
The library intentionally has **no compatibility with the old MixVcs API**.

## Why this design exists

Developers otherwise have to maintain two application workflows: a full
Git/RabbitMQ environment in production and mock directories during local
development. Switching those backends adds avoidable setup and branching
logic. `MixVcsManager` resolves full repository identifier + branch to a
mapped mock directory when enabled, otherwise to a passive remote handle.
Both return `Micx\Vcs\Repository\VcsRepository` with the same methods.
Concrete classes are `VcsMockRepository` and `VcsRemoteRepository` in the
`Micx\Vcs\Repository` namespace. A single manager may mix
mock and real repositories. In mock-only setups, `new MixVcsManager()`
requires no connection or shared mount.

Production isolates Git, SSH keys, credentials and repository access inside
the dedicated VCS worker. The PHP SDK uses RabbitMQ **only for Git control
commands and metadata**, never for transfer of repository file contents.
The worker and one or more other services mount the **same shared storage**.
This supports multiple service instances with a common checked-out working
tree. SDK processes serialize Git checkout, pull, commit and push using
per-repository-and-branch filesystem locks under `.mix-vcs-sdk/` in the
shared volume. Direct access bypassing the SDK needs separate coordination.

## Configuration and errors

- Remote: `new MixVcsManager(sharedDirectory: '/mix/vcs', connector: 'rabbitmq://user:pass@rabbitmq:5672/micx.vcs.v1')`.
- The explicit shared directory must already exist, be absolute and readable;
  the worker's `/data` volume must be mounted there. It is never created by
  the SDK. Applies also when the caller supplies an `RpcTransport` instance.
- Local development: `new MixVcsManager()` plus
  `setAllowMockDir(true)` and `addMockDir($sshUrl, 'main', $mockDirectory)`.
  The directory must exist, but may be outside shared storage.
- Exact repository URL and branch match selects the local mock without
  initiating a RabbitMQ connection. With a connector, unmapped URLs use
  remote checkout; without one, they throw `RepositoryNotFoundException`
  (`MIX-VCS-3005`). Missing shared storage is `MIX-VCS-1006`.
- `connector` also accepts `null`, `mock`, `file`, mock/file URI selectors
  or a supplied `RpcTransport`. URL connections initialize lazily.
  `Micx\\Vcs\\Transport\\TransportFactory` validates connector URLs, opens
  RabbitMQ connections and verifies a channel on first remote use.
  `RabbitMqTransport`, `RpcTransport`, `RpcException` and
  `OperationTimeoutException` reside in `Micx\\Vcs\\Transport`.
- The optional RabbitMQ URL path selects the **topic exchange** (default
  `micx.vcs.v1`), not the vhost. The vhost remains `/`, routing key stays
  `rpc.request`; the worker queue must be bound to the configured exchange.
- `RpcClient` and `WorkspaceRegistry` live under
  `Micx\\Vcs\\Helper\\Workspace`; `MixVcsManager` is the only root class.
- Mock commits use `.mix-vcs.json` for metadata and content hashes, not
  Git snapshots; mock pull does not contact a remote.

**Only example:** [examples/mixed-repositories.php](examples/mixed-repositories.php) — shows
mixed production/development configuration, a mocked SSH URL, a real SSH
URL, and commented mock-only constructor alternatives.

`getRepository($url, $branch = 'main')` only constructs the object. It does
not transfer data, open RabbitMQ, perform checkout, pull or push.
`getDirectory()` is also RPC-free: for mocks it returns the existing mapped
directory immediately; for remotes it consults shared-volume checkout
metadata written by the most recent successful pull in any SDK process.
If no checkout is registered or its directory has disappeared,
`RepositoryNotReadyException` (`MIX-VCS-2008`) is raised. A separate worker
or job should call `pull()` to initialize/update the remote checkout.
`sync()` performs pull followed by push; it does not auto-commit files.

`VcsRepository::ping(float $timeout = 5.0): bool` checks connectivity
without checkout or pull. Mock implementations return `true` immediately.
Remote implementations send a worker `ping` request with a per-call RPC
timeout, returning the boolean `pong`. A positive ping only confirms worker
connectivity, not SSH readiness or repository permissions. Invalid timeout
values throw `InvalidArgumentException`; RPC failures throw typed exceptions.

`Micx\Vcs\Repository\VcsRepository` exposes `ping`, `getDirectory`, `pull`, `sync`,
`commit`, `push`, `hasUnpushedChanges`, `getHistory` and `getBranches`.
Production `log`, `branches` and `status.hasUnpushedChanges` need worker
RPC extensions before those calls work for real Git repositories.
See [docs/error-codes.md](docs/error-codes.md) for typed exception groups,
numbered errors and troubleshooting.
